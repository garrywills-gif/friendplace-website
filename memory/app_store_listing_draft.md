## 9. App Review Notes
*(For the Apple reviewer — explains anything that might trip up review)*

```
Thank you for reviewing YouBelong.

ABOUT THE APP
YouBelong is a friendship community for older adults (50+). It is NOT a dating app. We explicitly prohibit romantic/sexual content in our Community Guidelines (available in Settings → Community Guidelines), and our reporting categories include "Dating-app behaviour" as a top-level reason.

DEMO ACCOUNT FOR TESTING
Email: reviewer-demo@youbelongapp.com
Password: ReviewMe!2026
This account is a regular member (not admin) so you can experience the standard user journey.

USER GENERATED CONTENT — MODERATION
We comply with App Review Guideline 1.2 (UGC apps) via:

1. EFP — Easily Find & Report
   Every screen with user-generated content has Block + Report icons.
   - Profiles: 3-dot menu top-right → Block / Report user
   - DMs: Long-press a message → Report
   - Group posts: 3-dot menu on each post → Report
   - Coffee Lounge messages: Long-press → Report

2. MECHANISM TO FILTER OBJECTIONABLE CONTENT
   - Profanity filter on all text inputs (server-side regex + blocklist)
   - Image moderation: photos screened on upload via Apple's NSFW detection (planned: full server-side moderation by build 1.1)

3. REPORTED-CONTENT WORKFLOW
   - Reports land in admin queue within seconds
   - Moderators review within 24 hours
   - Confirmed violations: warning → temporary suspension → permanent ban
   - Reporter is notified of outcome

4. ABILITY TO BLOCK ABUSIVE USERS
   - Block is one tap from any user surface
   - Blocked users cannot find, view, or message you. Mutual disappearance.

5. PUBLISHED EULA / CONTACT
   - Terms of Use: Settings → Legal → Terms (also in-app at /legal/terms)
   - Privacy Policy: Settings → Legal → Privacy Policy (in-app at /legal/privacy)
   - Contact: support@youbelongapp.com

IN-APP ACCOUNT DELETION (Guideline 5.1.1(v))
Users can delete their account at any time from Settings → Delete Account. We surface a confirmation modal ("Are you sure? This action cannot be undone.") and the action permanently removes profile, messages, posts, and friend connections. Group posts are anonymised so other members' threads remain coherent.

SIGN-IN OPTIONS
Version 1.0 supports email/password and Sign in with Google. Sign in with Apple will be added in build 1.1 per Guideline 4.8.

DEEP LINKS
The app uses the youbelong:// URL scheme for invite links (e.g. youbelong://invite/<code>). Test link: youbelong://invite/REVIEWER (opens to the invite-accept screen).

LOCATION USE
Location is used only to suggest events and friends in the user's suburb. We never store precise GPS coordinates; only suburb-level data after the user confirms it.

Thanks for taking the time to review — happy to clarify anything.
```

## 10. App Privacy (Data Disclosure)

Apple wants this declared in App Store Connect → App Privacy. Here's what to tick:

| Data Type | Used For | Linked to User | Used for Tracking |
|---|---|---|---|
| Email Address | App Functionality, Account Management | Yes | No |
| Name | App Functionality | Yes | No |
| Photos | App Functionality (profile pic, chat photos) | Yes | No |
| Coarse Location (Suburb) | App Functionality (find nearby) | Yes | No |
| User Content (messages, posts) | App Functionality | Yes | No |
| Crash Data | Diagnostics | No | No |
| Performance Data | Diagnostics | No | No |

**Do NOT tick:** Health & Fitness, Financial Info, Sensitive Info, Browsing History, Contacts (we ask for permission but don't store them — only the matching is server-side ephemeral), Tracking across apps.

## 13. Pre-Submission Checklist

- [ ] All screenshots uploaded (6.7" iPhone, 5.5" iPhone, 12.9" iPad — required sizes)
- [ ] App icon uploaded (1024×1024 PNG, no transparency, no rounded corners)
- [ ] App preview video (optional but boosts conversions ~25% per Apple stats)
- [ ] Privacy Policy URL is live
- [ ] Support URL is live (or mailto: link)
- [ ] Bundle ID matches the TestFlight build
- [ ] Demo account is active and functional
- [ ] Reviewer notes pasted into App Review Information field
- [ ] All keyword fields filled, no character overruns
- [ ] Age rating set to 17+
- [ ] App Privacy disclosures match what the app actually collects
- [ ] No reference to "dating", "meet", "hookup", or romantic language anywhere
- [ ] Sign-In requirement met (Apple Sign-In if you offer Google) — flagged for build 1.1

## 14. Reviewer Mental Model — Things That Could Get YouBelong Rejected

| Risk | Mitigation |
|---|---|
| Reviewer assumes it's a dating app | Explicit "NOT a dating app" copy in description, onboarding, community guidelines. Reviewer notes call it out. |
| Guideline 4.8 (Sign-in with Apple required if other 3rd-party sign-ins) | Add Apple Sign-In before PUBLIC submission (TestFlight is fine without). Currently flagged as build 1.1 work. |
| Guideline 1.2 (UGC moderation) | Reviewer notes detail the 5 EFP requirements + moderation SLA + block/report flows |
| Guideline 5.1.1(v) (in-app account deletion) | ✅ Already shipped — Settings → Delete Account |
| Privacy mismatch (App Privacy ≠ actual collection) | Reviewer-grade Privacy Policy + matching App Privacy disclosures |
| Crashes on first launch | TestFlight QA pass before submitting for review |
| Placeholder text or "lorem ipsum" | Final-pass copy review of every screen |
